- (note) Input: PRD, ARCHITECTURE-SPINE, DESIGN, EXPERIENCE; brief/addendum as sources
- (note) Why: GUI database clients cannot reach closed-contour hosts; SSH + psql/mongosh fragments the work; a small on-host TUI is the reliable path
- (capability) CAP-1 Connect from saved, imported, or new profiles; password resolved at connect and never stored
- (capability) CAP-2 Navigate one tree of databases, schemas, tables, collections, views, sequences, users, and roles with access markers
- (capability) CAP-3 Inspect object details: estimated count, size, indexes, structure, and exact count on demand
- (capability) CAP-4 Browse paged rows/documents, filter loaded rows, run server-side regexp on a field, and toggle global case mode
- (capability) CAP-5 Inspect native grants and memberships for the connected user and selected users/roles
- (capability) CAP-6 Compose and run one SQL/MQL statement with completion, help, history, and Results/errors in one tab
- (capability) CAP-7 Start every connection read-only, block write statements, and switch to read-write only after explicit confirmation
- (capability) CAP-8 Never leak secrets and never let database text control the terminal
- (capability) CAP-9 Operate keyboard-only at 80x24 with layout-independent keys and offline help
- (capability) CAP-10 Run as one static Linux binary with no runtime, daemon, listening ports, or telemetry
- (constraint) v1 engines: PostgreSQL 14+, MySQL 8.0+, MariaDB 10.4+, MongoDB 6.0+
- (constraint) One live connection per session; no tunnels, proxies, or GUI
- (constraint) Query bar holds one logical statement, up to three wrapped lines; no multi-statement scripts or arbitrary JavaScript
- (constraint) Read-only guard is a product safeguard, not a security boundary; writes only after an explicit switch
- (constraint) Passwords never persist; profiles are JSON with non-secret fields and an optional source pointer
- (constraint) TUI at 80x24, Nightshift, keyboard-first; DESIGN.md and EXPERIENCE.md are binding companions
- (constraint) Performance: cold start <300ms; first page <1s; data window 10k rows / 64MB
- (constraint) History: JSONL + TXT, 0600, redacted, 10MB x 5 rotation
- (constraint) Static binary for Linux amd64/arm64; no daemon, listening ports, telemetry, or update checks
- (constraint) ARCHITECTURE-SPINE AD-1..AD-13 are binding
- (constraint) Non-goal: not a GUI, DBeaver replacement, IDE, schema designer, or migration tool
- (constraint) Non-goal: no data editing, schema changes, or privilege assignment in v1
- (constraint) Non-goal: no full multi-line SQL editor, arbitrary JavaScript, or multi-statement scripts
- (constraint) Non-goal: no cross-engine query translation, backup, monitoring, or fleet management
- (constraint) Non-goal: no telemetry, cloud sync, saved passwords, shared profiles, SSO, or plugins in v1
- (constraint) Non-goal: no views/sequences data views, sorting, export, Windows, or additional engines in v1
- (note) Success: a week of on-host use without falling back to psql/mongosh; external tester completes both tasks; no credential leak
