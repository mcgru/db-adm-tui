# db-adm-tui v1.5.0

_Дата релиза: 2026-11-20_

_[English](release-notes-v1.5.0.md) | Русский_

Релиз делает матрицу доступа читаемой, когда имена ролей содержат суффикс базы.

## Ориентация матрицы

- `1 Role × Principal`: роли теперь слева, пользователи/principals — в
  столбцах, для PostgreSQL, MySQL/MariaDB и MongoDB.
- Длинные имена вроде `readWriteAnyDatabase@admin` остаются в широкой левой
  колонке и не сжимаются в заголовке ячейки.
- `2 Principal/Role × Object`: principals/роли остаются слева, объекты — в
  столбцах; эта ориентация уже даёт длинным именам широкую сторону. Подсказка
  полного имени усечённого столбца работает и там.

## Компактные подписи

- Пользователи MongoDB в `admin` показываются без `@admin`; пользователи в
  другой базе сохраняют `@database`.
- MySQL-столбцы скрывают стандартный host `%`; нестандартный host остаётся.
- Если имя текущего столбца не помещается в ячейку, полное имя показывается
  после `Tab switch` в заголовке матрицы.

## Privilege details

- `Ctrl+A` в multi-select деталей привилегий выбирает все привилегии списка или
  снимает все, если уже выбраны все.

## Обнаружимость

Вкладки Details/Privileges для `Security`, `users`, `roles` и отдельных
principal теперь показывают `Ctrl+X Ctrl+R opens the access matrix (r/w)`.

## Особенности движков

- PostgreSQL: имена ролей и пользователей короткие и без базы; транспонирование
  в основном даёт больше места длинным ролям.
- MySQL/MariaDB: столбцы `user@host` скрывают `@%`, роли остаются слева;
  `user@host` сохраняется для нестандартных хостов.
- MongoDB: строки `role@db` слева, столбцы `user`/`user@db` сверху, built-in
  роли остаются видимыми.

Изменений профилей, state и формата данных нет.
